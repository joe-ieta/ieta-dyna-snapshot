# Ieta Dyna Snapshot Release

## Workflow

1. Start from the repository root `E:\CodexDev\ieta-dyna-snapshot`.
2. Inspect current worktree status first with `git status -sb`; do not revert unrelated user changes.
3. Build the release with:

```powershell
node scripts/build-release.mjs
```

Use `--portable-only` when the user wants a platform-neutral package skeleton without copying the current machine's `node_modules`, Node runtime, or Playwright browser cache.

4. If the script needs to write the sibling release directory, copy the local Node runtime, copy Playwright cache, or launch Playwright during validation, request sandbox escalation when required.
5. Validate the source build first through the script's built-in `pnpm type-check` and `pnpm build` steps. Then validate the release package with:

```powershell
E:\CodexDev\ieta-dyna-snapshot-release\test-release.cmd
```

On Linux ARM64, use:

```bash
cd /opt/ieta-dyna-snapshot-release
chmod +x ./install-runtime.sh ./start.sh ./test-release.sh
./install-runtime.sh
./test-release.sh
```

## Release Contract

- The release directory defaults to `E:\CodexDev\ieta-dyna-snapshot-release`.
- Runtime data must stay under the release directory: `data`, `logs`, `runtime/browser-profiles`, and `runtime/ms-playwright`.
- Windows start command: `.\start.cmd`.
- Linux ARM64 start command: `./start.sh`.
- Linux ARM64 may need a system Chromium path in `.env` via `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`.
- Keep documentation concise and Chinese-facing: `README.md`, `docs/安装使用手册.md`, and `docs/测试文档.md` are generated by the release script.

## Notes

- Do not edit generated files inside the release directory by hand unless the user asks for a one-off hotfix; update `scripts/build-release.mjs` and regenerate instead.
- If dependency installation is needed on a target machine, use `install-runtime.ps1` or `install-runtime.sh` from inside the release directory so `node_modules`, pnpm store, Playwright browsers, data, and logs remain colocated.
